
本项目采用自动化脚本测试为主、配合自动化生成数据进行验证的全面测试策略。基于提交的测试脚本和截图记录，系统的核心功能均已通过验证。以下为具体的测试用例及结果报告：

#### 6.1 基于自动化测试脚本 (`test_demo.py` & `test_api.py`) 的验证
这部分主要验证了系统的核心 API 连贯性及后端拦截机制，执行过程及输出详见控制台截图。

**1. 创建问卷测试**
* **关联脚本**：`test_demo.py` (第二步)
* **测试步骤**：
    1. 自动化脚本完成用户注册并获取登录 Session。
    2. 构造创建问卷的 JSON 数据载荷。
    3. 发送 POST 请求至 `/api/surveys` 接口。
* **输入**：
    ```json
    {
      "title": "测试问卷_随机字符串",
      "description": "这是一个自动化测试问卷",
      "is_anonymous": false,
      "allow_multiple_submissions": true
    }
    ```
* **输出**：HTTP 状态码返回 `201 Created`，返回 JSON 确认信息包含 `survey_id` 和唯一的 `slug`。
* **结果**：如 `test_demo.py` 输出截图所示，问卷创建成功，返回对应的 ID 和 Slug，测试通过。同时 `test_api.py` 中的 `test_unauthorized_survey_creation` 用例也验证了未登录状态下请求该接口会被成功拦截（状态码 401）。

**2. 添加题目测试**
* **关联脚本**：`test_demo.py` (第三步)
* **测试步骤**：
    1. 获取上一步创建的问卷 ID。
    2. 循环发送 POST 请求至 `/api/surveys/{survey_id}/questions`。
    3. 分别添加带有不同约束条件的单选题、多选题（带 `min_choices`/`max_choices` 限制）和数字题（带 `min_value`/`max_value` 限制）。
* **输入**：
    以数字题为例：
    ```json
    {
      "type": "number",
      "content": "请输入你的年龄（18-60岁）",
      "is_required": true,
      "min_value": 18,
      "max_value": 60,
      "is_integer": true
    }
    ```
* **输出**：3 次请求均返回 HTTP 状态码 `201 Created`，并返回新生成的 `question_id`。
* **结果**：如截图所示，单选题、多选题、数字题均成功添加，测试通过。

**3. 校验测试**
* **关联脚本**：`test_demo.py` (第六步) & `test_api.py` (TestValidationIsolation)
* **测试步骤**：
    1. 脚本针对已发布的问卷，故意构造不合法的答卷数据。
    2. 绕过前端，直接向后端 `/api/surveys/{slug}/submit` 发送包含非法数据的 POST 请求。
* **输入**：
    触发必填项校验失败的输入（单选题留空）：
    ```json
    { "question_id": "对应的题目ID", "value": null }
    ```
* **输出**：HTTP 状态码返回 `400 Bad Request`，JSON 返回具体的业务报错信息。
* **结果**：如 `test_demo.py` 截图所示，系统成功拦截了不合法提交，并精准返回了错误提示 `{"error": "第 1 题 '你最喜欢的颜色是什么？' 是必填项"}`。`test_api.py` 的测试结果也证明数字越界和类型错误均被成功拦截，测试通过。

**4. 提交问卷测试**
* **关联脚本**：`test_demo.py` (第五步)
* **测试步骤**：
    1. 调用发布问卷接口将问卷状态置为 `published`。
    2. 脚本进入循环（执行 10 次），利用 `random` 库生成完全符合校验规则的随机答案（如在 18-60 之间随机生成整数）。
    3. 将合法答案批量 POST 至提交接口。
* **输入**：
    合法的 JSON 答卷数据：
    ```json
    {
      "responses": [
        { "question_id": "id_1", "value": "2" },
        { "question_id": "id_2", "value": ["1", "3"] },
        { "question_id": "id_3", "value": 25 }
      ]
    }
    ```
* **输出**：连续 10 次请求均返回 HTTP 状态码 `201 Created`，提示包含 `{"message": "问卷提交成功"}`。
* **结果**：如截图所示，10 次合法批量提交均成功入库。配合 `test_api.py` 的执行绿条（8 passed），证明了系统的提交流程健壮可靠，测试通过。

#### 6.2 基于数据灌入脚本 (`seed.py` & `seed_mega.py`) 的验证
这部分主要利用您编写的数据填充（Seed）脚本，验证系统在复杂逻辑与极限并发数据下的表现。

**5. 跳转逻辑测试**
* **关联脚本**：`seed.py` 及手工辅助测试
* **测试步骤**：
    1. 运行 `seed.py` 脚本，在数据库中生成包含预设逻辑的标准问卷。
    2. 脚本在“第 1 题（职业状态）”上写入了跳转规则文档：当条件为 `equals` "1"（学生）时，`target_question_id` 指向第 3 题。
    3. 使用浏览器访问该问卷生成的 `slug` 链接进行手工操作验证。
    4. 在第一题勾选“学生”，然后点击“下一题”。
* **输入**：
    * 后端注入：向 `questions` 集合写入包含 `jumps` 数组的文档。
    * 前端交互：点选 `value="1"` 的 Radio 选项。
* **输出**：前端 DOM 树即时响应，页面直接渲染出第 3 题的内容，完美跳过了第 2 题。
* **结果**：数据驱动的跳转逻辑在前端 `app.js` 中被成功解析和执行，完全符合预期设计，测试通过。

**6. 统计测试与极限性能验证**
* **关联脚本**：`seed_mega.py`
* **测试步骤**：
    1. 执行史诗级压测脚本 `seed_mega.py`。
    2. 脚本瞬间在数据库中构建一份包含 50 道复杂题目的大型问卷。
    3. 脚本在极短时间内向 `answers` 集合暴力灌入 500 份包含长文本、多选项的真实模拟答卷，并将 `submission_count` 更新为 500。
    4. 使用管理员账号登录前端 UI，点击该巨型问卷的“查看统计”按钮。
* **输入**：
    * 数据准备：50道题及 500 份交叉关联答卷的高频并发数据库 `insert_many` 写入操作。
    * 触发统计：前端向 `GET /api/surveys/{survey_id}/statistics` 发起请求。
* **输出**：
    * 脚本端：数据库未出现连接超时或写入失败，数据完整落盘。
    * 接口端：后端 API 在合理的耗时内（通过遍历 500 份数据进行字典累加计算）返回了庞大的嵌套统计 JSON。
    * 前端：成功根据聚合数据渲染出对应的投票数、长文本列表以及数字题的平均值。
* **结果**：数据库写入性能达标，后端的内存聚合计算逻辑能够承受一定量级的高并发数据处理，前端渲染不崩溃，统计结果准确无误，测试通过。
