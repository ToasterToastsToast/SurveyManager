# 阶段二测试说明

本项目采用自动化脚本测试为主、配合手工测试验证的全面测试策略。基于提交的测试脚本 `megatest.py`，系统的核心功能均已通过验证。以下为具体的测试用例及结果报告：

## 6.1 基于自动化测试脚本 (`megatest.py`) 的验证

这部分主要验证了系统的核心 API 连贯性及后端拦截机制，执行过程及输出详见控制台截图。

### 1. 题目创建与复用测试

* **关联脚本**：`megatest.py` (TestQuestionReuse 类)
* **测试步骤**：
  1. 自动化脚本完成用户注册并获取登录 Session。
  2. 创建问卷 A 并添加题目 Q1。
  3. 创建问卷 B 并复用题目 Q1。
  4. 验证复用是否创建了独立的题目副本。
* **输入**：
  - 创建题目：`{"type": "text", "content": "原始题目", "is_required": true}`
  - 复用题目：`{"question_id": "q_id"}`
* **输出**：
  - 复用成功返回新的题目 ID
  - 两个题目文档共享同一 base_question_id
* **结果**：如 `megatest.py` 输出所示，复用题目时会创建独立的副本，保证原题目的 used_in_surveys 不被污染，测试通过。

### 2. 题目共享测试

* **关联脚本**：`megatest.py` (TestQuestionSharing 类)
* **测试步骤**：
  1. 创建题目并设置为公开或分享给指定用户。
  2. 另一个用户尝试复用该题目。
  3. 验证权限控制。
* **输入**：
  - 分享题目：`{"is_public": true, "shared_with_users": []}`
* **输出**：
  - 分享成功返回 200 OK
  - 非所有者尝试分享返回 403 Forbidden
  - 公开题目可被其他用户复用
* **结果**：如 `megatest.py` 输出所示，题目分享功能正常，权限控制有效，测试通过。

### 3. 题目修改隔离测试（核心）

* **关联脚本**：`megatest.py` (TestPublishedSurveyProtection 类)
* **测试步骤**：
  1. 创建问卷并添加题目。
  2. 发布问卷。
  3. 尝试修改已发布问卷中的题目。
  4. 验证修改是否被拒绝。
* **输入**：
  - 修改题目：`{"survey_id": "s_id", "content": "尝试修改已发布问卷中的题目"}`
* **输出**：
  - 已发布问卷的题目修改请求返回 403 Forbidden
  - 原题目内容保持不变
* **结果**：如 `megatest.py` 输出所示，已发布问卷的题目不可被直接修改，有效防止了历史问卷被污染，测试通过。

### 4. 版本管理测试

* **关联脚本**：`megatest.py` (TestQuestionHistory 类)
* **测试步骤**：
  1. 创建题目并多次修改。
  2. 访问题目历史记录。
  3. 验证历史记录的完整性和顺序。
* **输入**：
  - 多次修改题目内容
  - 访问历史：`GET /api/questions/{q_id}/history`
* **输出**：
  - 历史记录包含所有版本
  - 版本按升序排列
  - 版本号随修改递增
* **结果**：如 `megatest.py` 输出所示，题目修改历史记录完整，版本管理功能正常，测试通过。

### 5. 多版本并存测试

* **关联脚本**：`megatest.py` (TestQuestionVersionCoexistence 类)
* **测试步骤**：
  1. 创建题目 Q1 并复用到问卷 B。
  2. 修改问卷 B 中的题目副本。
  3. 验证问卷 A 和问卷 B 的题目内容是否独立。
* **输入**：
  - 复用题目到新问卷
  - 修改副本内容：`{"survey_id": "sb_id", "content": "新版本内容"}`
* **输出**：
  - 问卷 A 的题目内容保持不变
  - 问卷 B 的题目内容已更新
* **结果**：如 `megatest.py` 输出所示，不同版本的题目可以同时存在，供不同问卷独立使用，测试通过。

### 6. 题目使用追踪测试

* **关联脚本**：`megatest.py` (TestQuestionUsage 类)
* **测试步骤**：
  1. 创建题目并复用到多个问卷。
  2. 访问题目使用情况。
  3. 验证使用情况的准确性。
* **输入**：
  - 访问使用情况：`GET /api/questions/{q_id}/usage`
* **输出**：
  - 返回题目被使用的问卷列表
  - 非所有者访问返回 403 Forbidden
* **结果**：如 `megatest.py` 输出所示，题目使用追踪功能正常，权限控制有效，测试通过。

### 7. 题库管理测试

* **关联脚本**：`megatest.py` (TestQuestionBank 类)
* **测试步骤**：
  1. 创建题库。
  2. 向题库添加题目。
  3. 从题库中移除题目。
  4. 验证公开题库的访问权限。
* **输入**：
  - 创建题库：`{"name": "我的题库", "description": "常用题目集合", "is_public": false}`
  - 添加题目：`{"question_id": "q_id"}`
* **输出**：
  - 题库创建、更新、删除操作成功
  - 题目可成功添加到题库和从题库移除
  - 公开题库可被其他用户访问
* **结果**：如 `megatest.py` 输出所示，题库管理功能完整，权限控制有效，测试通过。

### 8. 跨问卷统计测试

* **关联脚本**：`megatest.py` (TestCrossSurveyStatistics 类)
* **测试步骤**：
  1. 创建多个问卷并复用同一题目。
  2. 提交问卷回答。
  3. 访问跨问卷统计接口。
  4. 验证统计结果的准确性。
* **输入**：
  - 提交回答：`{"responses": [{"question_id": "q_id", "value": 8}]}`
  - 访问统计：`GET /api/questions/{q_id}/statistics`
* **输出**：
  - 统计结果包含所有问卷的数据
  - 数字题计算平均值
  - 文本题汇总所有回答
  - 非所有者访问返回 403 Forbidden
* **结果**：如 `megatest.py` 输出所示，跨问卷统计功能正常，数据汇总准确，测试通过。

### 9. 端到端集成测试

* **关联脚本**：`megatest.py` (TestEndToEnd 类)
* **测试步骤**：
  1. 创建题目 → 分享 → 复用 → 修改（版本分裂）
  2. 查询历史 → 恢复 → 查看使用情况 → 跨问卷统计
* **输入**：
  - 完整的题目生命周期操作
* **输出**：
  - 所有操作均成功完成
  - 数据一致性得到保证
* **结果**：如 `megatest.py` 输出所示，完整的题目生命周期流程测试通过，系统集成正常。

## 6.2 手工测试验证

除了自动化测试外，我们还设计了一套手工测试流程，用于验证前端交互及用户体验。

### 1. 题目创建与复用

**测试目标**：验证“题目独立存在 + 可复用”

**测试步骤**：
1. 进入“题目管理”页面
2. 创建新题目：“你的年龄”
3. 保存
4. 创建新问卷，选择“从已有题目添加”
5. 选择“你的年龄”
6. 创建另一个问卷，再次添加“你的年龄”

**预期结果**：
- 题目成功创建并在列表中显示
- 题目成功加入问卷，未重新创建新题
- 两个问卷引用同一逻辑题目（通过 base_question_id 关联）

### 2. 题目共享

**测试目标**：验证题目可被他人使用

**测试步骤**：
1. 用户 A 创建题目并点击“共享”
2. 设置为公开或指定用户 B
3. 用户 B 登录并创建问卷
4. 从“共享题目”中选择用户 A 的题目

**预期结果**：
- B 能看到 A 的题目
- B 可正常使用该题目
- A 仍保留该题的所有权

### 3. 题目修改隔离（核心）

**测试目标**：确保“历史问卷不被污染”

**测试步骤**：
1. 创建问卷 A（未发布），使用题目 Q1
2. 修改 Q1，验证问卷 A 内容同步变化
3. 发布问卷 A
4. 尝试修改 Q1，验证系统是否拒绝或提示创建新版本
5. 查看问卷 A，验证其仍使用 Q1（旧版本）

**预期结果**：
- 未发布问卷中的题目可直接修改
- 已发布问卷中的题目不可直接修改，需创建新版本
- 已发布问卷的内容保持不变

### 4. 版本管理

**测试目标**：验证版本链正确

**测试步骤**：
1. 创建 Q1，修改生成 Q2，再修改生成 Q3
2. 打开题目详情，查看“版本历史”
3. 尝试恢复到 Q1 版本

**预期结果**：
- 版本历史显示 v1 → v2 → v3 关系
- 恢复旧版本后生成新版本 Q4（基于 Q1）
- Q3 仍然存在，不被覆盖

### 5. 多版本并存

**测试目标**：验证“分支使用”

**测试步骤**：
1. 创建 Q1，修改生成 Q2
2. 问卷 A 使用 Q1，问卷 B 使用 Q2
3. 分别查看两个问卷的内容

**预期结果**：
- 两个问卷内容不同
- 互不影响

### 6. 题目使用追踪

**测试目标**：防止误修改

**测试步骤**：
1. 创建 Q1，被问卷 A、B 使用
2. 查看 Q1 的“使用情况”
3. 尝试修改 Q1，观察系统提示

**预期结果**：
- “使用情况”显示问卷 A 和问卷 B
- 修改时系统提示：“该题正在被 X 个问卷使用”
- 提供选项：创建新版本或取消

### 7. 题库管理

**测试目标**：验证“题库作为集合容器”

**测试步骤**：
1. 新建题库“常用问题”
2. 将 Q1 加入题库
3. 创建问卷，从题库选题
4. 更新 Q1 → Q2，查看题库中的版本变化

**预期结果**：
- 题库创建成功
- 题目成功加入题库
- 从题库选题成功
- 题库中可看到题目版本变化

### 8. 跨问卷统计

**测试目标**：验证“同题聚合统计”

**测试步骤**：
1. Q1 被问卷 A、B 使用
2. 各自收集数据
3. 查看 Q1 的跨问卷统计
4. 创建 Q2（Q1 的新版本），用于问卷 C，收集数据后查看统计

**预期结果**：
- 展示问卷 A+B 的汇总数据
- 不同版本的统计数据分开显示

## 6.3 关键风险点（必须重点测试）

1. **版本污染**
   - 修改题目影响历史问卷（严重 bug）
   - 测试方法：修改已发布问卷中的题目，验证历史问卷内容是否变化

2. **引用 vs 复制混淆**
   - 是否真的共享同一逻辑题目对象
   - 测试方法：检查不同问卷中复用的题目是否共享 base_question_id

3. **版本链断裂**
   - 找不到来源版本
   - 测试方法：查看题目历史记录，验证版本链的完整性

4. **统计口径错误**
   - 不同版本被错误合并
   - 测试方法：验证不同版本的题目统计数据是否正确分开

5. **权限问题**
   - 共享题是否越权访问
   - 测试方法：非所有者尝试访问或修改他人的题目

## 6.5 测试执行建议

1. **执行顺序**：先运行自动化测试脚本 `megatest.py`，再进行手工测试
2. **环境准备**：确保 MongoDB 服务正常运行，应用服务器启动
3. **数据清理**：每次测试前清理数据库，避免历史数据干扰
4. **测试记录**：详细记录测试过程和结果，特别是异常情况
5. **回归测试**：每次代码修改后，重新运行测试脚本确保功能未回归

通过以上测试策略，我们可以全面验证系统的功能正确性、稳定性和用户体验，确保满足需求变更中的所有要求。
