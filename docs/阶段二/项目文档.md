### 一、 系统说明

**1. 项目概述**
本项目是一个基于 MongoDB 开发的在线问卷系统，在第一阶段的基础上进行了大规模功能扩展。系统不仅保留了原有的问卷创建、发布、填写和统计功能，还新增了题目管理、版本控制、题库管理等高级特性，实现了题目复用、共享和跨问卷统计等核心功能。

**2. 技术栈选型**
本项目在第一阶段的技术栈基础上进行了扩展，继续采用前后端分离的架构思路：
* **后端语言**：Python
* **后端框架**：Flask（利用轻量级路由和内置 Session 进行鉴权）
* **数据库**：MongoDB（通过 `pymongo` 驱动交互，本地持久化存储）
* **前端方案**：原生 HTML/CSS 结合 **Alpine.js**（实现轻量级的响应式数据绑定和单页面应用 SPA 体验）
* **密码加密**：`bcrypt`（保障用户凭据安全）
* **测试框架**：`pytest`（用于后端 API 的自动化测试保障）

**3. 核心功能模块**
系统在第一阶段的基础上，新增了以下核心模块：

* **用户权限模块**（增强）
    * 保留原有的账号注册与加密登录功能。
    * 增强了权限隔离机制：支持题目和题库的共享，实现了基于用户的细粒度权限控制。

* **题目管理模块**（新增）
    * **题目独立存在**：题目不再隶属于特定问卷，成为独立的系统资源。
    * **题目复用**：支持将已有题目复用到多个问卷中，避免重复创建。
    * **题目共享**：支持将题目设置为公开或分享给特定用户，实现资源共享。
    * **版本控制**：实现题目版本的创建、追踪和恢复，确保修改题目不会影响已发布问卷。
    * **使用追踪**：记录题目在哪些问卷中被使用，防止误修改。

* **题库管理模块**（新增）
    * **题库创建与管理**：支持创建个人或共享题库，用于整理和管理常用题目。
    * **题目加入题库**：支持将题目加入题库，方便后续复用。
    * **从题库选题**：创建问卷时可直接从题库中选择题目。

* **问卷与题目管理模块**（增强）
    * 保留原有的问卷管理、题型支持、高级校验和跳转逻辑功能。
    * 增强了题目管理能力，支持从已有题目添加和管理题目版本。

* **数据统计分析模块**（增强）
    * 保留原有的问卷统计功能。
    * 新增了跨问卷统计功能，基于同一题目的不同版本进行数据汇总。

**4. 系统架构与设计思路**
* **前后端交互**：前端通过 `api.js` 封装的 Fetch 请求调用后端的 RESTful API，实现数据的 JSON 格式收发。
* **无感序列化**：继续使用自定义的 `MongoJSONProvider`，全局自动处理 MongoDB 的 `ObjectId` 和 `Datetime` 对象的 JSON 序列化问题。
* **高内聚低耦合**：在第一阶段的基础上，进一步引入了工厂/策略模式，将题目版本管理、权限控制等逻辑解耦，保证了系统的可扩展性。
* **版本隔离机制**：实现了“写时复制”机制，确保修改题目时自动创建新版本，避免影响已发布问卷。


### 二、 数据库设计

本项目在第一阶段的基础上，对数据结构进行了重大重构，引入了新的集合和字段，以支持题目管理、版本控制和题库管理等新功能。

#### 4.1 核心集合 Schema 说明

**1. 用户集合 (`users`)**
* `_id`: ObjectId，主键。
* `username`: String，用户名。
* `password`: String，加密存储的密码。
* `created_at`: Date，注册时间。
* `email`: String，可选，预留找回密码功能。
* `created_surveys`: ArrayObjectId]，用户创建的问卷 ID 列表。
* `submitted_answers`: ArrayObjectId]，用户提交的答卷 ID 列表。
* `question_banks`: ArrayObjectId]，用户拥有或加入的题库 ID 列表（**新增**）。

**2. 问卷集合 (`surveys`)**
* `_id`: ObjectId，主键。
* `user_id`: ObjectId，创建该问卷的用户 ID。
* `title`: String，问卷标题。
* `description`: String，问卷说明。
* `is_anonymous`: Boolean，是否允许匿名填写。
* `allow_multiple_submissions`: Boolean，是否允许多次填写。
* `status`: String，问卷状态（draft 草稿, published 已发布, closed 已关闭）。
* `expire_at`: Date，截止时间。
* `slug`: String，生成的唯一短链接标识。
* `question_count`: Number，问题总数（冗余设计）。
* `submission_count`: Number，收集到的答卷总数（冗余设计）。
* `questions`: ArrayObject]，问卷包含的题目及上下文属性（**新增**）。
    * `question_id`: ObjectId，题目的 ID。
    * `order`: Number，题目在问卷中的显示顺序。
    * `is_required`: Boolean，是否必答。
    * `jumps`: ArrayObject]，跳转规则。

**3. 题目集合 (`questions`)**
* `_id`: ObjectId，主键。
* `base_question_id`: ObjectId，同一题目的所有版本共享此 ID（**新增**）。
* `version`: Number，版本号（**新增**）。
* `previous_version_id`: ObjectId，上一版本 ID（**新增**）。
* `owner_id`: ObjectId，题目创建者（**新增**）。
* `is_public`: Boolean，是否公开（**新增**）。
* `shared_with_users`: ArrayObjectId]，共享给的用户 ID 列表（**新增**）。
* `used_in_surveys`: ArrayObjectId]，被使用的问卷 ID 列表（**新增**）。
* `type`: String，题型（single_choice, multiple_choice, text, number）。
* `content`: String，题目内容。
* `options`: ArrayObject]，选择题的选项数组（包含 id, text, value）。
* **约束条件字段**（根据题型动态生效）：
    * `min_choices` / `max_choices`: 多选题的选择数量限制。
    * `min_length` / `max_length`: 文本题的字数限制。
    * `min_value` / `max_value` / `is_integer`: 数字题的范围和类型限制。

**4. 答卷集合 (`answers`)**
* `_id`: ObjectId，主键。
* `survey_id`: ObjectId，所属问卷 ID。
* `user_id`: ObjectId，填写者 ID（若为匿名填写则为 null）。
* `created_at`: Date，提交时间。
* `responses`: ArrayObject]，具体的回答内容数组。
    * `question_id`: ObjectId，对应题目的 ID。
    * `base_question_id`: ObjectId，题目的基础 ID（**新增**）。
    * `value`: Mixed，回答的原始值（单选为字符串，多选为数组）。
    * `text`: String，针对填空题的文本记录。

**5. 题库集合 (`question_banks`)**（**新增**）
* `_id`: ObjectId，主键。
* `name`: String，题库名称。
* `description`: String，题库描述。
* `owner_id`: ObjectId，题库创建者。
* `is_public`: Boolean，是否公开。
* `shared_with_users`: ArrayObjectId]，共享给的用户 ID 列表。
* `questions`: ArrayObjectId]，包含的题目 `base_question_id` 列表。

---

#### 4.3 设计决策分析 (Design Decisions)

**1. 为什么这样设计？** 
本设计在第一阶段的基础上，采取了“题目独立化”与“版本控制”相结合的策略。
* **题目独立化**：将题目从问卷中分离出来，成为独立的系统资源，实现了题目复用和共享的基础。
* **版本控制**：通过 `base_question_id`、`version` 和 `previous_version_id` 字段，实现了题目版本的追踪和管理，确保修改题目不会影响已发布问卷。
* **题库管理**：新增 `question_banks` 集合，为用户提供了一个整理和管理常用题目的容器。
* **跨问卷统计**：基于 `base_question_id`，实现了同一题目在多个问卷中的数据汇总，提供了更全面的统计分析能力。

**2. 为什么这种结构特别适合 MongoDB？** 
* **Schema-Free（无模式）的优势**：MongoDB 的文档模型完美契合了“异构数据”的存储需求，支持题目版本的灵活存储和管理。
* **内嵌数组的强力支持**：MongoDB 极擅长处理具有强生命周期绑定的子属性，如问卷中的题目列表、题目的选项和跳转规则。
* **高效的查询能力**：MongoDB 的索引机制和聚合框架，为题目版本查询、跨问卷统计等操作提供了高效的支持。
* **水平扩展能力**：MongoDB 的分布式架构，为系统处理大量题目和问卷数据提供了良好的扩展性。

### 三、 API 说明

本项目后端采用 RESTful API 设计风格，所有接口均通过 JSON 格式进行数据交换。除问卷填写相关接口外，大部分接口要求用户处于登录状态。

#### 1. 通用说明
* **Base URL**: `/api`
* **Content-Type**: `application/json`
* **认证方式**: 基于 Flask Session 的 Cookie 认证。执行登录后，后续请求需携带 Session Cookie。

---

#### 2. 用户认证 API
用于处理用户的注册、登录、登出及身份检查。

* **用户注册**
    * **URL**: `POST /api/register`
    * **请求体**: `{ "username": "...", "password": "...", "email": "..." }`
    * **功能**: 创建新用户，密码经过 bcrypt 加密存储。

* **用户登录**
    * **URL**: `POST /api/login`
    * **请求体**: `{ "username": "...", "password": "..." }`
    * **响应**: 返回登录成功的用户信息，并在 Cookie 中设置 Session。

* **获取当前用户信息**
    * **URL**: `GET /api/me`
    * **功能**: 检查当前登录状态，返回当前用户的 ID 和用户名。

---

#### 3. 问卷管理 API (需登录)

* **获取问卷列表**
    * **URL**: `GET /api/my_surveys`
    * **功能**: 返回当前登录用户创建的所有问卷列表。

* **创建问卷**
    * **URL**: `POST /api/surveys`
    * **请求体**: `{ "title": "...", "description": "...", "is_anonymous": true/false, "expire_at": "ISO-Date" }`
    * **功能**: 初始化问卷基本信息，生成唯一的 `slug` 用于分发。

* **添加题目**
    * **URL**: `POST /api/surveys/<survey_id>/questions`
    * **请求体**: 包含题目类型、内容、选项及校验规则。

* **从已有题目添加**
    * **URL**: `POST /api/surveys/<survey_id>/add_existing_question`
    * **请求体**: `{ "question_id": "..." }`
    * **功能**: 将已有题目复用到问卷中。

* **更新题目**
    * **URL**: `PUT /api/questions/<question_id>`
    * **请求体**: 包含题目内容、选项及校验规则。
    * **功能**: 修改题目内容，自动创建新版本。

* **发布/关闭问卷**
    * **URL**: `POST /api/surveys/<survey_id>/publish` 或 `/api/surveys/<survey_id>/close`
    * **功能**: 修改问卷状态。只有“已发布”状态的问卷才允许外部填写。

---

#### 4. 题目管理 API (需登录)

* **获取题目列表**
    * **URL**: `GET /api/questions`
    * **功能**: 返回当前登录用户可访问的题目列表（包括自己创建的和共享的）。

* **创建题目**
    * **URL**: `POST /api/questions`
    * **请求体**: 包含题目类型、内容、选项及校验规则。

* **获取题目详情**
    * **URL**: `GET /api/questions/<question_id>`
    * **功能**: 返回题目的详细信息。

* **分享题目**
    * **URL**: `PUT /api/questions/<question_id>/share`
    * **请求体**: `{ "is_public": true/false, "shared_with_users": [...] }`
    * **功能**: 设置题目的共享权限。

* **获取题目历史版本**
    * **URL**: `GET /api/questions/<question_id>/history`
    * **功能**: 返回题目的所有历史版本。

* **恢复旧版本**
    * **URL**: `POST /api/questions/<question_id>/restore`
    * **请求体**: `{ "version_id": "..." }`
    * **功能**: 基于旧版本创建新版本。

* **获取题目使用情况**
    * **URL**: `GET /api/questions/<question_id>/usage`
    * **功能**: 返回题目在哪些问卷中被使用。

* **获取题目统计**
    * **URL**: `GET /api/questions/<question_id>/statistics`
    * **功能**: 返回题目在所有问卷中的统计结果。

---

#### 5. 题库管理 API (需登录)

* **获取题库列表**
    * **URL**: `GET /api/question_banks`
    * **功能**: 返回当前登录用户可访问的题库列表（包括自己创建的和共享的）。

* **创建题库**
    * **URL**: `POST /api/question_banks`
    * **请求体**: `{ "name": "...", "description": "...", "is_public": true/false }`

* **获取题库详情**
    * **URL**: `GET /api/question_banks/<bank_id>`
    * **功能**: 返回题库的详细信息和包含的题目。

* **更新题库**
    * **URL**: `PUT /api/question_banks/<bank_id>`
    * **请求体**: `{ "name": "...", "description": "...", "is_public": true/false, "shared_with_users": [...] }`

* **删除题库**
    * **URL**: `DELETE /api/question_banks/<bank_id>`

* **向题库添加题目**
    * **URL**: `POST /api/question_banks/<bank_id>/add_question`
    * **请求体**: `{ "question_id": "..." }`

* **从题库移除题目**
    * **URL**: `DELETE /api/question_banks/<bank_id>/remove_question/<question_id>`

---

#### 6. 问卷填写与提交 API

* **获取填写页问卷数据**
    * **URL**: `GET /api/fill_survey/<slug>`
    * **功能**: 根据 URL 中的 Slug 获取问卷标题、描述及完整的题目列表。会检查问卷是否过期或关闭。

* **提交问卷答案**
    * **URL**: `POST /api/surveys/<slug>/submit`
    * **请求体**: `{ "responses": [ { "question_id": "...", "value": "...", "text": "..." }, ... ] }`
    * **功能**: 后端 `QuestionValidator` 会逐题校验答案合法性，校验通过后将答卷存入 `answers` 集合。

---

#### 7. 统计分析 API (需登录)

* **获取问卷统计结果**
    * **URL**: `GET /api/surveys/<survey_id>/statistics`
    * **功能**: 实时聚合 `answers` 集合中的数据。

### 四、 关键逻辑说明

系统的核心业务逻辑主要集中在题目管理、版本控制、权限隔离以及跨问卷统计四个方面。为了兼顾代码的健壮性与可扩展性，本系统在逻辑实现上采用了诸多设计模式与优化手段。

#### 5.1 题目管理逻辑（独立化与复用）
* **题目独立化**：题目不再隶属于特定问卷，成为独立的系统资源，通过 `base_question_id` 关联同一题目的不同版本。
* **题目复用**：当用户将题目复用到问卷中时，系统会创建题目副本，确保原题目的 `used_in_surveys` 不被污染。
* **题目共享**：支持将题目设置为公开或分享给特定用户，实现资源共享。

#### 5.2 版本控制逻辑（写时复制）
* **写时复制**：当用户修改题目时，系统会自动创建新版本，保留原有版本，确保已发布问卷的内容不受影响。
* **版本链管理**：通过 `previous_version_id` 字段，维护题目版本的演进链，支持查看历史版本和恢复旧版本。
* **版本隔离**：已发布问卷中的题目版本被锁定，防止被修改，确保历史问卷的一致性。

#### 5.3 权限控制逻辑（细粒度权限）
* **题目权限**：题目拥有者和被共享用户可以访问和使用题目。
* **题库权限**：题库拥有者和被共享用户可以访问和使用题库。
* **操作权限**：只有题目拥有者可以修改题目和管理共享权限。

#### 5.4 跨问卷统计逻辑（基于 base_question_id）
* **数据聚合**：基于 `base_question_id`，聚合同一题目在多个问卷中的回答数据。
* **统计策略**：针对不同题型，采用不同的统计策略，如选择题计算各选项的得票数，数字题计算平均值等。
* **版本区分**：不同版本的题目统计数据分开显示，确保统计结果的准确性。

#### 5.5 前端状态管理逻辑（URL 驱动）
* **URL 驱动状态**：采用 URL 驱动的状态管理机制，确保页面刷新后状态正确恢复。
* **模态框管理**：统一的模态框管理机制，避免模态框错误弹出。
* **数据绑定**：利用 Alpine.js 实现轻量级的数据绑定，提升用户体验。

#### 5.6 测试与验证逻辑（自动化测试）
* **自动化测试**：使用 `pytest` 框架，实现了覆盖所有核心功能的自动化测试。
* **端到端测试**：实现了完整的端到端测试，验证了系统的集成性。
* **异常边界测试**：通过注入非法数据，验证了系统的异常处理能力。

通过以上关键逻辑的实现，系统不仅满足了需求变更中的所有要求，还保持了良好的可扩展性和可维护性，为未来的功能扩展打下了坚实的基础。
